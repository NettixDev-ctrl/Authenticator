# Как помочь проекту

Спасибо за интерес! Ниже — коротко о том, как предложить изменение.

## Сообщить о проблеме

Откройте Issue и опишите:

- что вы делали и что ожидали увидеть;
- что произошло на самом деле;
- версию приложения и операционную систему.

**Не прикладывайте `accounts.json`, экспортированные резервные копии и скриншоты с действующими кодами** —
это ваши секретные ключи. Если проблема воспроизводится только с конкретным ключом, создайте
одноразовый тестовый аккаунт.

## Предложить изменение

1. Сделайте форк и создайте ветку от `main`.
2. Убедитесь, что тесты проходят:
   ```sh
   npm install
   npm test
   ```
3. Опишите в Pull Request суть изменения и, если это влияет на интерфейс, приложите скриншот
   до и после.

## Стиль кода

- Исходники намеренно компактные: главный процесс и логика TOTP держатся в нескольких файлах,
  чтобы их можно было прочитать целиком.
- Логика TOTP, разбор ключей и резервные копии живут в отдельных модулях (`otp.js`, `backup.js`)
  и покрыты тестами. Изменения там стоит сопровождать тестом.
- Интерфейс — без внешних библиотек и сборщиков: обычные HTML, CSS и JavaScript.
- Тексты интерфейса и документации — на русском языке.

## Что важно не сломать

- **Секреты не должны попадать в renderer-процесс.** Интерфейс получает только готовые коды
  и метаданные; ключи остаются в главном процессе.
- **Никаких сетевых запросов для генерации кодов.**
- **Никаких новых зависимостей без необходимости** — приложение намеренно почти не имеет их,
  кроме `jsqr`.
- **Данные пользователя неприкосновенны.** Файл `accounts.json` не должен изменяться,
  если операция завершилась ошибкой.
